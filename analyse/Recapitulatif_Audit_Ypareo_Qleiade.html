Récapitulatif de l'Audit Ypareo - Projet Qléiade

🎯 Contexte Stratégique Global

Cet audit s'inscrit dans une démarche globale de cartographie des appels à l'API REST d'Ymag (BDES, iResto, Qléiade, etc.). Suite au changement de facturation de l'éditeur reposant désormais sur un système de paliers liés au volume de requêtes, et eu égard au positionnement actuel de la structure dans la tranche la plus haute, l'objectif est d'identifier de manière précise et isolée les foyers de consommation par application, afin d'optimiser ensuite globalement les services les plus sollicités.

1. Objectif sur l'Application Qléiade

L'audit du code du projet Qléiade a permis d'isoler l'ensemble des appels réalisés vers l'API Rest Ypareo, leurs contextes d'utilisation dans la structure du code (principalement sur le back-office Filament) et les données manipulées.

Le tableau de bord central (TDB Usages API Rest Ypareo - TdB.csv) a été complété par les lignes propres au projet "Qléiade" en respectant la structure de votre document de pilotage général.

Environnements cartographiés : L'analyse englobe les deux instances du projet (liées à la même base métier Ymag ymag.cloud) :

  • Qléiade Production (qleiade.cite-formations-tours.fr)
  • Qléiade Pré-Production (qleiade-dev.cite-formations-tours.fr)

2. Découvertes Clés : Mappage des Endpoints et Déclencheurs

Quatre requêtes réelles se distinguent au sein du fichier app/Filament/Admin/Resources/Wealths/WealthResource.php, particulièrement liées à la granularité des "Preuves" (Wealth) :

  1. Formations (getFormations) : Récupère la liste de toutes les formations via /r/v1/formations.
    📌 Fonctionnalité : Création / Édition d'une Preuve
    ⚡ Déclencheur UI : À chaque fois que l'utilisateur ouvre/charge la liste déroulante des "Formations" dans le formulaire de Preuve.
  2. Périodes Scolaires (getPeriods) : Récupère via /r/v1/periodes l'intégralité des périodes.
    📌 Fonctionnalité : Création / Édition d'une Preuve
    ⚡ Déclencheur UI : À chaque fois que l'utilisateur charge la liste déroulante des "Apprenants" (nécessaire pour filtrer la période).
  3. Apprenants FI (apprenants) : Récupère via /r/v1/formation-longue/apprenants les apprenants en "Formation Initiale".
    📌 Fonctionnalité : Création / Édition d'une Preuve
    ⚡ Déclencheur UI : À chaque fois que l'utilisateur charge la liste déroulante des "Apprenants" dans le formulaire (pour les lister).
  4. Recherche Unitaire Apprenant (searchStudent) : Trouve les informations détaillées d'un apprenant unitaire via /r/v1/rechercher/apprenants.
    📌 Fonctionnalité : Analyse API / Visualisation (Liste des Preuves)
    ⚡ Déclencheur UI : À chaque fois que l'application affiche à l'écran une preuve liée à un apprenant (dans un tableau ou en vue détaillée).
(Note : L'intégration technique est gérée et centralisée par la classe SchoolManager et le composant Guzzle Connecter.php).

3. 🚨 Pistes d'Optimisation Potentielles (Alerte Volume)

Dans la perspective d'une réduction globale du volume d'appels API, le code de Qléiade révèle trois foyers d'appels "à risques" par rapport à sa propre utilisation (modérée ou non). Ces points pourraient contribuer, à leur échelle, à la surconsommation totale mesurée par Ymag :

Impact Massif Potentiel 1. Multiplicateur de requêtes N+1 :
Dans la vue détaillée d'une preuve ou dans des tableaux Filament (TextEntry::make('granularity_unified')), le code interroge Ypareo (searchStudent()) de manière unitaire pour chaque apprenant rattaché à une ligne.

Le point de vigilance : Si le back-office devait afficher 50 preuves simultanées liées à des apprenants distincts, le serveur lancerait mécaniquement 50 appels REST synchrones et consécutifs. Ce comportement d'une vue peut être un gros contributeur s'il est utilisé de manière récurrente.
Impact Fort Potentiel 2. L'absence de cache sur des référentiels statiques :
Lors de la création ou de l'édition d'une preuve liée à l'Entité "Formation", Qléiade fait un appel systématique à l'API Ymag pour rapatrier le catalogue entier des formations, uniquement pour alimenter une liste déroulante (select field).

Le point de vigilance : En l'absence de système de cache local, ce lourd catalogue est re-passé dans les requêtes de serveurs Ymag pour chaque simple ouverture de ce formulaire spécifique.
Impact Moyen Potentiel 3. Les appels itératifs imbriqués (Foreach) :
Lors de la construction de la vue permettant de sélectionner un stagiaire, le code itère dynamiquement (foreach ($periodIds as $periodId)) sur les périodes en cours pour lancer autant d'appels API apprenants qu'il y a de périodes scolaires actives.

Le point de vigilance : C'est un multiplicateur fixe du paramètre de requête qui n'est pas optimisé via une seule requête de groupe mais bien via un appel déclenché par période lors de l'ouverture du champ.

4. Renseignement du Rapport et Indicateurs Complémentaires

Afin de finaliser l'audit et donner plus de relief à l'analyse, les données complémentaires suivantes ont été insérées :

  • Fonctionnalité et Interactions : La colonne "Fréquence" et "Cycle" détaillent désormais précisément le parcours fonctionnel ("Création / Édition") et les déclencheurs UI explicites provoquant la requête, afin de compenser par la théorie l'absence de trafic chiffré.
  • Population Estimée : La consultation de la base de données indique une population cible précise de 19 utilisateurs inscrits pouvant potentiellement utiliser l'application. Cette limite fixe permet de relativiser la portée brute des appels de Qléiade vis-à-vis des autres systèmes.
  • Environnements (Prod / Pré-prod) : Les deux instances applicatives de Qléiade ont été correctement dupliquées et assignées à leurs domaines de rattachement effectifs dans le tableau de bord CSV. Ces deux instances sollicitent d'ailleurs la même base mutualisée ymag.cloud.

5. ✅ Solution Technique Validée pour une Phase Ultérieure

Stratégie de Caching Actée

Afin d'endiguer efficacement la volumétrie décrite aux points 3.1 et 3.2, et après confirmation fonctionnelle, la solution technique pertinente retenue pour une intervention future est l'implémentation robuste d'un Cache (local File ou Redis) au sein des méthodes d'interface métier (ex. SchoolManager).

  • Mise en cache des Référentiels (Formations, Périodes) : Permettra de ne faire qu'un seul appel ponctuel à l'API Ymag par jour (ou par 12h) tout en conservant la structure en mémoire pour tous les affichages des listes déroulantes de Filament.
  • Mise en cache ou Synchronisation de l'Annuaire Apprenant : Viendra enrayer l'impact dévastateur des requêtes "N+1" générées lors d'affichages unitaires consécutifs sur des listes ou l'administration des "Preuves".

Cette optimisation technique sera opérée et appliquée selon le niveau de priorité accordé à Qléiade une fois la cartographie globale finalisée sur l'ensemble de l'écosystème numérique ciblant Ypareo.
